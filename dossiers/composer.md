# composer (Cursor Composer 2.5)

**Lean-in:** IDE-native implementer. Parallel edits, fast iteration. Don't write a design doc.

## Training / harness

Cursor's own coding agent, Terminal-Bench / CursorBench flavored, IDE tools first-class. Faster and cheaper than Grok 4.6 on a lot of mechanical multi-file work. Weaker independent prior than Grok or Opus — good second Cursor model when you want two *Cursor* takes without leaving the plan, but same-product huddle is a smaller disagreement than Grok vs Opus.

## Wins

- Multi-file mechanical implementation in Cursor
- Parallel agent-shaped work
- Cheap Cursor-plan worker when Grok is the senior

## Reluctance / failure modes

- Same product as Grok — from Cursor, this is still *you*; native Task, not `peers composer`
- Can leave a multi-file change half-followed-through
- Not the review brain

## How to use without hindering

Point at the files. Acceptance test. Don't pair it with Grok and expect a philosophical disagreement — pick Opus/Codex for that.
