# Dossiers

Priors about each peer — nitty-gritty, not marketing. Used three ways:

1. **Router** (`dossiers.py`) — keyword rules pick *who*. The model never sees this.
2. **Lean-in** — two sentences in the prompt. Permission to use that prior. Not a costume.
3. **Full file** — this folder. The peer Reads it only when counterpart behavior matters (huddle/review).

Dumping these essays into every prompt hinders: Claude starts verify-loops, Grok writes a manifesto, everyone roleplays. Keep the prompt tiny.

Gateway names (Z.AI, Kimi, Ollama, …) get a lean-in in `dossiers.py`. Add a file here when a pattern repeats.

Observations from real huddles land in `$PEERS_HOME/observed.md` (default `~/.local/share/peers/desk/observed.md`). Promote into these files when a pattern repeats — don't auto-rewrite with an LLM.

Claims mix public evals with harness behavior. Treat numbers as leads, not law. The desk's own `observed.md` outranks a blog.
